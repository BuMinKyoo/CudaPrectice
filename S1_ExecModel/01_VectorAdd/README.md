# 01_VectorAdd — 블록 크기와 grid-stride (S1-1)

## 배울 것
- `<<<grid, block>>>` 런치, 전역 인덱스 `blockIdx.x * blockDim.x + threadIdx.x`
- `if (i < n)` 가드가 왜 필요한가 (grid×block 은 n 보다 크게 반올림됨)
- **warp = 32 스레드** → 블록 크기를 32의 배수로 잡는 이유
- **grid-stride loop**: 스레드 수와 데이터 크기를 분리하는 표준 패턴
- 시간은 `GpuTimer`(cudaEvent)로 잰다 — 이유는 03 예제에서

## 참고 — 메모리 계층 (00_DeviceQuery 출력 읽는 법)

### VRAM 과 공유 메모리는 별개의 물리 메모리다

```
VRAM 8 GB           GPU 칩 "바깥" 기판 위의 GDDR6 칩들     <- cudaMalloc 이 잡는 곳
공유 메모리 96KB/SM  GPU 칩 "안쪽" 각 SM 에 박힌 SRAM      <- __shared__ 가 쓰는 곳
```

종류가 다른 반도체(DRAM vs SRAM)라 속도가 수십 배 차이 난다.
공유 메모리는 **8GB 에 포함되지 않는다.** cudaMalloc 으로 8GB 를 꽉 채워도
각 SM 의 96KB 는 그대로 남아 있다. RTX 4060 기준 공유 메모리 총량은
96KB x 24 SM = 2.25 MB 로, VRAM 과 무관하게 따로 존재한다.

| 위치 | 어디 | 지연 | 범위 |
|---|---|---|---|
| 레지스터 | 스레드 전용 | ~1 사이클 | 스레드 하나 |
| 공유 메모리 | **SM 안 (칩 안)** | ~30 사이클 | **블록 하나** |
| L2 캐시 | GPU 다이 공용 | ~200 사이클 | 전체 |
| 전역 = VRAM | **칩 바깥 (기판)** | ~500 사이클 | 전체 |
| 시스템 RAM | PCIe 건너 | — | — |

### shared mem/block 과 shared mem/SM 이 왜 둘 다 있나

```
shared mem/block : 49152 bytes (48.0 KB)   <- 블록 하나가 최대로 쓸 수 있는 양
shared mem/SM    : 98304 bytes (96.0 KB)   <- SM 전체가 가진 양
```

물리적으로는 SM 당 하나지만, **블록마다 칸을 나눠 준다.**

```
┌──────── SM 0 의 공유 메모리 96KB (물리적으로 하나) ────────┐
│  ┌─ 블록A ─┐ ┌─ 블록B ─┐ ┌─ 블록C ─┐ ┌─ 블록D ─┐          │
│  │ A만 봄  │ │ B만 봄  │ │ C만 봄  │ │ D만 봄  │          │
│  └─────────┘ └─────────┘ └─────────┘ └─────────┘          │
│        서로 넘볼 수 없다 (칸막이)                           │
└───────────────────────────────────────────────────────────┘
```

블록이 SM 에 올라갈 때 자기 몫을 떼어 받고, 끝나면 반납해서 다음 블록이 쓴다.
두 숫자가 따로 있다는 것 자체가 "나눠 쓴다" 는 증거다.

**블록 간에는 공유할 수 없다.** 이유는 세 가지다.
- 동시에 상주한다는 보장이 없다 (블록 0 과 블록 15000 은 만날 일이 없다)
- 어느 SM 에 배정될지 모른다 (물리적으로 다른 칩 구역이면 공유 자체가 불가능)
- 같은 바이너리가 SM 8개 GPU 와 132개 GPU 에서 모두 돌아야 한다

블록 간에 값을 주고받아야 하면 전역 메모리를 쓰고, 동기화는 커널을 나누는 것으로 한다
(커널 경계 = 모든 블록이 끝난 지점 = 사실상 유일한 전역 동기화 수단).

### occupancy 제약이 하나 늘어난다

블록마다 떼어 가므로, 공유 메모리를 많이 쓰면 SM 에 블록이 덜 올라간다.

```
① 블록 자리        max blocks/SM
② warp/스레드 자리  max threads/SM
③ 공유 메모리      shared mem/SM ÷ 블록당 사용량     <- 여기가 추가
④ 레지스터         registers/SM ÷ 블록당 사용량

SM 당 블록 수 = 위 넷 중 제일 작은 값
```

블록당 48KB 를 꽉 쓰면 98304 / 49152 = **2 블록**밖에 안 올라간다.
공유 메모리가 occupancy 를 직접 깎는 상황이다. (실제 예는 04_Transpose)
