# 07_Streams — 전송과 겹치기 (S5)

## 왜 이 예제가 필요한가

`03_AsyncAndErrors` 는 **"커널 런치는 비동기다"** 까지 가르치고 끝났다.
그런데 정작 쓸 때는 매번 이렇게 썼다.

```c
Kernel<<<...>>>();
cudaDeviceSynchronize();      // <- 이것 말고 다른 걸 배운 적이 없다
```

**비동기를 배웠는데 동기적으로밖에 못 쓴다.** 그걸 여기서 닫는다.

그리고 `01_VectorAdd` 에서 확인한 숙제가 하나 더 있다.

```
커널 0.5 ms  vs  H2D 6.6 ms + D2H 3.7 ms
-> 전체의 95% 가 복사였고, 왕복까지 세면 GPU 가 CPU 보다 3배 느렸다
```

이 예제는 그 복사 시간을 두 가지 방법으로 줄인다.

1. **pinned memory** 로 복사 자체를 빠르게
2. **복사와 커널을 겹쳐서** 돌려 따로 걸리는 시간을 없애기

## 네 가지 방식 (하는 일은 전부 같다)

| | 방식 | 바뀌는 것 |
|---|---|---|
| A | pageable + 동기 복사 | 01 에서 쓰던 방식. 기준선 |
| B | **pinned** + 동기 복사 | 메모리 종류만. 구조는 A 와 동일 |
| C | pinned + **비동기** + 스트림 1개 | 겹칠 상대가 없다 |
| D | pinned + 비동기 + **스트림 N개** | 드디어 겹친다 |

**B → C 가 중요하다.** 거의 차이가 없어야 정상이다.
**"비동기로 부르는 것"과 "실제로 겹치는 것"은 다른 이야기**라는 뜻이다.

## pageable vs pinned

| | 어떤 메모리인가 | GPU 가 읽을 때 |
|---|---|---|
| **pageable** | 보통의 `malloc`/`new`. OS 가 언제든 디스크로 밀어낼 수 있다 | GPU 가 직접 못 읽는다. 드라이버가 내부 pinned 버퍼로 **한 번 더 복사**한 뒤 보낸다 |
| **pinned** | `cudaMallocHost`. OS 가 못 밀어내게 고정(page-locked) | GPU 가 **바로** 읽는다. 복사 한 번 |

```c
float* h = nullptr;
cudaMallocHost((void**)&h, bytes);   // 할당
...
cudaFreeHost(h);                     // 해제. free() 아니다
```

**그리고 더 중요한 것 — `cudaMemcpyAsync` 는 pinned 에서만 진짜로 비동기다.**
pageable 로 부르면 드라이버가 조용히 동기 복사로 처리해 버린다. 에러도 안 난다.
그래서 D 에 가려면 B 를 반드시 거쳐야 한다.

주의: pinned 는 물리 메모리를 잡아두는 것이라 **많이 쓰면 시스템 전체가 느려진다.**
필요한 만큼만 잡고 반드시 `cudaFreeHost` 한다.

## 겹치기의 구조

조각으로 잘라 파이프라인처럼 흘려보낸다.

```
조각0: [H2D][커널][D2H]
조각1:      [H2D][커널][D2H]       <- 조각0 이 커널 도는 동안 조각1 을 올린다
조각2:           [H2D][커널][D2H]
```

```c
for (int c = 0; c < nChunks; ++c) {
    int s = c % nStreams;
    cudaMemcpyAsync(dev + off, host + off, chunkBytes, H2D, st[s]);
    Work<<<grid, block, 0, st[s]>>>(dev + off, chunkN, iters);
    cudaMemcpyAsync(host + off, dev + off, chunkBytes, D2H, st[s]);
}
cudaDeviceSynchronize();      // 전부 끝날 때까지 여기서 한 번만 기다린다
```

**같은 스트림 안에서는 순서가 보장되고, 다른 스트림끼리는 겹칠 수 있다.**
한 조각의 H2D → 커널 → D2H 순서는 지켜지면서, 조각들끼리는 겹친다.

`<<<grid, block, 0, stream>>>` 의 **네 번째 인자**가 스트림이다.
세 번째는 공유 메모리 크기(05 에서 쓴 그것). 안 쓰면 0.

## 실행

```
07_Streams.exe [MB] [iters] [streams] [chunks]
기본: 128 MB, iters 50, streams 4, chunks 16
```

`iters` 는 커널 작업량이다. **커널 시간이 전송 시간과 비슷해야 겹침이 보인다.**
커널이 너무 무거우면 전송을 다 숨겨도 커널 시간은 그대로라 비율이 안 변하고,
너무 가벼우면 전송이 다 차지한다.

| B) pinned + 동기 | | |
| C) pinned + 비동기 1스트림 | | |
| D) pinned + 비동기 N스트림 | | |

구성 요소: H2D ___ ms / 커널 ___ ms / D2H ___ ms

## P2000 에서 실제로 나온 결과 — 교과서대로 안 됐다

```
[Quadro P2000] asyncEngineCount = 1, concurrentKernels = 1

pageable :  11.8 ms (11.4 GB/s)
pinned   :  10.8 ms (12.4 GB/s)   -> 1.09x      <- 기대보다 작다

H2D 10.8 / 커널 25.0 / D2H 15.2  =  단순 합 51.2 ms

A) pageable + 동기        48.6 ms   1.00x
B) pinned   + 동기        48.5 ms   1.00x
C) pinned   + 비동기 1스트림 44.9 ms   1.08x
D) pinned   + 비동기 4스트림 44.0 ms   1.11x    <- 숨길 수 있던 26 ms 중 28% 만 숨겼다
```

**교과서에서 보던 2배 같은 숫자가 안 나온다.** 왜 그런지가 이 예제의 진짜 내용이다.

### 이유 1 — 복사 엔진이 하나뿐이다

```
asyncEngineCount = 1
```

| 값 | 의미 |
|---|---|
| 0 | 복사와 커널을 아예 못 겹친다 |
| **1** | **한 방향씩만 겹친다.** H2D 와 D2H 는 서로 못 겹친다 |
| 2 | H2D, 커널, D2H 셋을 동시에 겹칠 수 있다 |

복사 엔진이 하나면 H2D(10.8) + D2H(15.2) = **26 ms 가 그 엔진에서 줄을 선다.**
커널은 25 ms. 그러면 이론 하한은 "커널만"(25 ms)이 아니라

```
max(커널, H2D + D2H) = max(25, 26) = 26 ms
```

이다. **애초에 숨길 수 있는 양이 생각보다 적다.**

### 이유 2 — Windows WDDM 드라이버

Windows 에서 일반 그래픽 카드는 **WDDM 모드**로 돈다. OS 가 GPU 스케줄링을 쥐고
있어서 드라이버가 명령을 **묶어서(batch)** 보낸다. 잘게 겹치는 것이 잘 안 된다.

- **Linux** 에서는 같은 코드가 훨씬 잘 겹친다
- Quadro/Tesla 는 **TCC 모드** 로 바꾸면 OS 를 거치지 않는다 (`nvidia-smi -dm 1`,
  단 그 GPU 로 화면을 못 띄우게 된다)

### 이유 3 — 측정 편차

같은 설정으로 여러 번 돌리면 "커널만" 이 15 ~ 25 ms 사이에서 흔들린다.
클럭 부스트 때문이다. **한 번 재고 결론 내면 안 된다.**

### 그래서 뭘 배우나

```
교과서: pinned + async + streams = 빨라진다
현실  : 내 환경이 그걸 지원하는지부터 확인해야 한다
```

이것이 04 에서 32x32 가 예상과 달랐던 것, 05 에서 2)/3) 차이가 안 보였던 것과
같은 종류의 교훈이다. **측정하지 않으면 모른다.**

그리고 숫자만으로는 "겹쳤는지" 를 알 수 없다. 타임라인을 봐야 확실하다:

```
nsys profile --stats=true 07_Streams.exe
```

## 해석 (직접 적기)

- 내 GPU 의 `asyncEngineCount` 는? 그 값이면 이론 하한이 얼마인가:
- B 와 C 가 거의 같게 나왔나? 그렇다면 그것이 뜻하는 바는:
- `iters` 를 10, 50, 200 으로 바꿔가며 D/A 비율이 어떻게 변하나.
  커널과 전송 중 어느 쪽이 길 때 겹침 효과가 커지나:
- 조각 수를 4, 16, 64 로 바꾸면? 너무 잘게 쪼개면 왜 오히려 느려지나:
- pinned 효과(A→B)가 작게 나왔다면, PCIe 대역폭이 이미 한계인지 확인해 볼 것
  (`pageable` 의 GB/s 가 이론 최대에 얼마나 가까운가)

## 생각해볼 것

  결과가 틀리나? 언제 틀리나?
- 스트림을 안 지정하면(기본 스트림) 왜 겹치지 않나?
  (기본 스트림은 다른 스트림들과 암묵적으로 동기화된다)
- `cudaStreamSynchronize(st[s])` 로 스트림 하나씩만 기다리면 뭐가 달라지나?
- 실시간 영상이라면: 프레임 N 을 처리하는 동안 프레임 N+1 을 올리려면
  버퍼가 몇 개 필요한가?
